    What this means

    RESEARCHED A phone on http://<LAN-or-USB-IP> is not a secure context: it can never register a Service Worker or use WebGPU. So a fresh phone cannot be bootstrapped to a runnable offline app by a peer over http alone.

    RESEARCHED The working model: visit the https origin once → the shell precaches and the SW registers. After that the device is offline-forever-capable; a peer need only ship the 131 MB model into transformers-cache (P2P), and the code runs from the already-secured cached origin.

    RESEARCHED iOS Safari never fires beforeinstallprompt; install is the manual Share → Add to Home Screen. Android/Chromium offers the one-tap button above when criteria are met.
